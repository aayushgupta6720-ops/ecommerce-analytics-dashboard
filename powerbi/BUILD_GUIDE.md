# Power BI build guide

This folder is a kit for rebuilding the Streamlit dashboard in Power BI. Everything here is generated by
`python scripts/export_powerbi.py` from the same cleaned data and the same metric code as the app, so
the two should show identical numbers. The [tie-out table](#tie-out-numbers) lets you check that.

| File | What it's for |
|---|---|
| `data/RetailAnalytics.xlsx` | All tables as sheets. Upload this in the browser (route A). |
| `data/*.csv` | Same tables, one CSV each. The PBIP project loads these (route B). |
| `measures.dax` | Every measure with its format and home table, ready to paste. |
| `measures_query.dax` | Power BI Desktop: creates all 18 measures at once in DAX query view and prints the tie-out numbers. |
| `DESKTOP_GUIDE.md` | Step-by-step build in **Power BI Desktop on Windows** (easiest route; no license needed). |
| `RetailAnalytics.pbip` + `.SemanticModel/` + `.Report/` | Generated Power BI Project (route B, **untested**). |

## The model

A star schema: one fact table and four dimensions, plus three precomputed analysis tables.

```
dim_date ─┐                 ┌─ dim_product ── product_returns
          ├── fact_sales ───┤
dim_country ┘               └─ dim_customer
cohort_retention, basket_rules: standalone (no relationships)
```

- **fact_sales**: one row per product invoice line, about 1.02M rows. Cancellations are kept, with
  `is_cancellation = TRUE` and a negative quantity. Postage, fees and manual adjustments are excluded,
  as in the app.
- **Relationships**: all many-to-one with single-direction filtering.
  - `fact_sales[invoice_date]` → `dim_date[date]`
  - `fact_sales[stock_code]` → `dim_product[stock_code]`
  - `fact_sales[customer_id]` → `dim_customer[customer_id]`
  - `fact_sales[country]` → `dim_country[country]`
  - `product_returns[stock_code]` → `dim_product[stock_code]`
- **Precomputed tables** (`dim_customer` RFM columns, `cohort_retention`, `basket_rules`, `product_returns`)
  are computed once over the full date range, so date and country slicers don't change them.
  Recomputing RFM scores or association rules live in DAX would be slow and hard to maintain. The
  Streamlit app does recompute them for every filter.

## Route A: Power BI in the browser (app.powerbi.com)

This route needs a work or school account; personal Gmail/Outlook accounts can't sign up.

1. **Create the semantic model.** Go to app.powerbi.com, open *My workspace*, and upload
   `data/RetailAnalytics.xlsx` as a new semantic model. Microsoft renames these menus often, so look
   for *New item → Semantic model* or *Upload → Browse*. Each sheet is formatted as an Excel table named
   after it (`fact_sales`, `dim_date`, ...), and those names become the model's table names that the
   measures refer to. The workbook is about 40 MB and 1M rows, so the upload takes a minute or two.
   - The service only imports data formatted as Excel tables. If it says it *couldn't find any data
     formatted as a table*, the workbook is from an older export; run `python scripts/export_powerbi.py`
     again.
   - If your tenant only offers Excel through OneDrive/SharePoint, put the workbook in OneDrive first
     and pick it from there.
2. **Open the model editor.** On the semantic model, choose *Open data model*. If that option is greyed
   out, *Edit data models in the Power BI service* has to be enabled in your workspace settings.
3. **Create the relationships** above under *Manage relationships*. Delete any that Power BI
   auto-detected differently, for example `fact_sales[country]` → `dim_customer[country]`.
4. **Mark `dim_date` as the date table.** Select the table, choose *Mark as date table*, and pick the
   `date` column.
5. **Set sort columns and hide helpers.**

   | Column | Sort by column |
   |---|---|
   | `dim_date[month_name]` | `month_num` |
   | `dim_date[weekday_name]` | `weekday_num` |
   | `dim_customer[segment]` | `segment_order` |

   Then hide `month_num`, `weekday_num` and `segment_order`.
6. **Check data types.**
   - `invoice` and `stock_code`: **Text**. Most values look like numbers (489434, 85123), but
     cancellations (`C489449`) and variants (`85123A`) don't. If Power BI guessed *Whole number*,
     change it back to Text before loading, or those rows become errors.
   - `is_cancellation` and `is_partial_month`: True/False
   - `customer_id`: whole number, with no summarization
   - dates: Date
   - `revenue`, `price` and `monetary`: decimal number
7. **Add the measures.** For each block in `measures.dax`:
   1. Select the home table named in the comment and choose *New measure*.
   2. Paste the block, then set the format and display folder given in the comment.
8. **Build the report pages** below by choosing *Create report → Start from scratch* on the model.
   Put the date slicer and the country slicer on every page except Customers, Cohorts and Market basket,
   and sync them (*View → Sync slicers*).

### Pages

Each page mirrors a Streamlit page. Field names are *table[column]*; measures are in **bold**.

1. **Overview**
   - Slicers: `dim_date[date]` (Between), `dim_country[country]`
   - Cards: **Revenue**, **Orders**, **Customers**, **Avg Order Value**, **Cancellation Rate**
   - Line chart: X `dim_date[month_start]`, Y **Revenue**. Optional: add **Revenue PY** as a second line
     on the same axis (same unit, so no second axis is needed).
   - Matrix: rows `dim_date[weekday_name]`, columns `fact_sales[hour]`, values **Orders**. Add a blue
     background colour scale via *Cell elements → Background color* to turn it into a heatmap.
   - Bar chart: Y `dim_country[country]`, X **Revenue**, sorted descending, filtered to the top 10
     by **Revenue**.
2. **Products**
   - Bar chart: `dim_product[description]` by **Revenue**, with a Top N = 10 filter
   - Table: `stock_code`, `description`, `abc_class`, **Revenue**, **Units**, **Orders**,
     **Pareto Cumulative %**
   - Line chart for the 80/20 curve: X `dim_product[revenue_rank]` (continuous axis), Y
     **Pareto Cumulative %**
3. **Geography**
   - Filled map: Location `dim_country[country]`. Set colour saturation / *Fill colors → fx* to
     **Revenue**, using a single blue gradient.
   - Table: country, region, **Revenue**, **Country Revenue Share**, **Orders**, **Customers**,
     **Avg Order Value**
   - Tip: add a filter `dim_country[country] ≠ United Kingdom`. The UK is about 85% of revenue and
     flattens the map.
4. **Customers (RFM)**
   - Treemap: Category `dim_customer[segment]`, Values **Segment Customers**
   - Clustered bar: Y `segment`, X **Segment Customer Share** and **Segment Revenue Share**. Both are
     percentages, so one axis is enough.
   - Table: segment with the four segment measures
5. **Cohort retention**
   - Matrix: rows `cohort_retention[cohort_label]`, columns `cohort_retention[period]`, values
     **Retention %**
   - Add a background colour scale, and filter `period ≠ 0` (month 0 is always 100%).
   - The Dec 2009 cohort includes pre-existing customers, because the data starts there.
6. **Market basket**
   - Slicer: `basket_rules[antecedent_desc]` (*Customers who bought…*)
   - Table: `antecedent_desc`, `consequent_desc`, `pair_baskets`, `support`, `confidence`, `lift`,
     sorted by `lift` descending
7. **Returns & cancellations**
   - Cards: **Cancelled Value**, **Cancellation Rate**, **Net Revenue**
   - Line chart: `dim_date[month_start]` by **Cancellation Rate**
   - Table from `product_returns`, sorted by `cancelled_value`
   - Two single orders cancelled in full (80,995 × Paper Craft Little Birdie on 9 Dec 2011 and
     74,215 × Medium Ceramic Top Storage Jar on 18 Jan 2011) account for about a third of all
     cancelled value.

### Formatting to match the app

- Import `RetailAnalytics.Report/StaticResources/RegisteredResources/RetailTheme.json` via
  *View → Themes → Browse for themes*. It holds the same palette the Streamlit charts use.
- Use one colour per chart unless a legend is needed.
- Don't use dual-axis charts. When two measures have different units, give each its own chart.

## Route B: the PBIP project (untested)

`RetailAnalytics.pbip` is a Power BI Project. The model is in TMDL files and the report is in PBIR
JSON files, all generated by `scripts/pbip.py`.

**What was checked:**
- `python scripts/validate_pbip.py` validates every JSON file against Microsoft's published schemas.
- It also checks that every table, column and measure referenced by measures, relationships and report
  visuals exists in the model.

**What wasn't checked:** whether Power BI actually opens the project. Nothing on macOS can open a PBIP,
so expect to fix a few things on first open.

**Power BI Desktop (Windows):**
1. Copy the whole `powerbi/` folder to the Windows machine and open `RetailAnalytics.pbip`.
   - Older Desktop versions need *File → Options → Preview features*: enable *Power BI Project (.pbip)
     save option*, *Store semantic model using TMDL format*, and *Store reports using enhanced metadata
     format (PBIR)*.
2. Go to *Transform data → Edit parameters* and set **DataFolder** to the full path of `powerbi\data\`,
   including the trailing backslash. Then choose *Refresh*.
3. If Desktop reports an error, copy the message and send it to me. The generator is easier to fix than
   the individual files.

**Fabric workspace with Git integration** (needs Fabric/Premium capacity, which many university
tenants don't have):
- Commit the `powerbi/` folder to the connected repo and sync.
- The CSV paths are local files, so refreshing in the service needs either an on-premises data gateway
  or a switch of the partitions from `File.Contents` to `Web.Contents` pointing at hosted CSVs
  (for example raw GitHub URLs).

## Regenerating

```bash
python scripts/export_powerbi.py            # CSVs, workbook, measures, PBIP, tie-out numbers
python scripts/export_powerbi.py --no-xlsx  # skip the slow workbook
python scripts/validate_pbip.py             # schema + reference checks
```
